## 3. ユースケース詳細

### UC-01: 新規ユーザー登録

| 項目 | 内容 |
|------|------|
| **概要** | 未登録ユーザーがメールアドレス・ユーザー名・パスワードを入力してアカウントを作成する |
| **事前条件** | ユーザーが未ログイン状態である |
| **基本フロー** | 1. 会員登録画面を開く<br>2. メールアドレス・ユーザー名・パスワード・パスワード確認を入力する<br>3. 「登録する」ボタンを押下する<br>4. 登録完了後、タイムライン画面へ遷移する |
| **代替フロー** | 3a. 入力値が不正な場合（メール形式エラー、パスワード不一致、重複メール）はエラーメッセージを表示して入力画面に留まる |
| **事後条件** | ユーザーアカウントが作成され、ログイン状態になる |

---

### UC-02: ログイン

| 項目 | 内容 |
|------|------|
| **概要** | 登録済みユーザーがメールアドレスとパスワードで認証し、アプリを利用できる状態にする |
| **事前条件** | ユーザーがアカウントを持ち、未ログイン状態である |
| **基本フロー** | 1. ログイン画面を開く<br>2. メールアドレスとパスワードを入力する<br>3. 「ログイン」ボタンを押下する<br>4. 認証成功後、タイムライン画面へ遷移する |
| **代替フロー** | 3a. 認証失敗の場合はエラーメッセージを表示する |
| **事後条件** | ログイン状態になり、全機能を利用できる |

---

### UC-03: ログアウト

| 項目 | 内容 |
|------|------|
| **概要** | ログイン中のユーザーがセッションを終了する |
| **事前条件** | ユーザーがログイン状態である |
| **基本フロー** | 1. プロフィール画面等からログアウトを選択する<br>2. セッションが破棄される<br>3. ログイン画面へ遷移する |
| **代替フロー** | なし |
| **事後条件** | ログアウト状態になり、認証が必要な画面にアクセスできなくなる |

---

### UC-04: タイムライン閲覧（全体）

| 項目 | 内容 |
|------|------|
| **概要** | 全ユーザーの旅行投稿を新着順で一覧表示する |
| **事前条件** | ユーザーがログイン状態である |
| **基本フロー** | 1. タイムライン画面を開く<br>2. 「タイムライン」タブを選択する<br>3. 全ユーザーの投稿が新着順に表示される<br>4. 各投稿カードには写真スワイプ・地名バッジ・本文・ハッシュタグ・いいね／行きたい！ボタンが表示される |
| **代替フロー** | 3a. 投稿が0件の場合は「まだ投稿がありません」を表示する |
| **事後条件** | 最新の投稿一覧が表示される |

---

### UC-05: タイムライン閲覧（フォロー中）

| 項目 | 内容 |
|------|------|
| **概要** | フォロー中のユーザーの投稿のみを新着順で表示する |
| **事前条件** | ユーザーがログイン状態である |
| **基本フロー** | 1. タイムライン画面を開く<br>2. 「フォロー中」タブを選択する<br>3. フォロー中ユーザーの投稿が新着順に表示される |
| **代替フロー** | 3a. フォロー中ユーザーが0人の場合は「フォロー中のユーザーがいません」を表示する<br>3b. フォロー中ユーザーの投稿が0件の場合は「まだ投稿がありません」を表示する |
| **事後条件** | フォロー中ユーザーの最新投稿一覧が表示される |

---

### UC-06: 旅行を投稿する

| 項目 | 内容 |
|------|------|
| **概要** | ユーザーが写真・本文・ハッシュタグ・地図ピンを投稿する |
| **事前条件** | ユーザーがログイン状態である |
| **基本フロー** | 1. BottomTabの「記録」ボタンを押下して投稿作成モーダルを開く<br>2. 写真を最大6枚選択する（選択と同時にサーバーへアップロード）<br>3. 各写真に任意で地図ピン（場所名・緯度経度）を設定する<br>4. 本文を入力する（任意）<br>5. ハッシュタグを入力する（任意）<br>6. 「投稿する」ボタンを押下する<br>7. 投稿がDBに保存され、タイムラインに反映される |
| **代替フロー** | 6a. 写真が未選択の場合はエラーを表示する（写真必須）<br>6b. 写真が7枚以上の場合はエラーを表示する<br>6c. 写真アップロード中は「投稿する」ボタンが無効化される<br>6d. 写真アップロード失敗の場合はエラーを表示し投稿を中断する |
| **事後条件** | 投稿がDBに保存され、タイムライン先頭に追加される |

---

### UC-07: 投稿を削除する

| 項目 | 内容 |
|------|------|
| **概要** | 自分の投稿を削除する |
| **事前条件** | ユーザーがログイン状態であり、削除対象が自分の投稿である |
| **基本フロー** | 1. 自分の投稿の「…」メニューから「投稿を削除」を選択する<br>2. ブラウザのネイティブ確認ダイアログが表示される<br>3. 「OK」を押下する<br>4. 投稿・写真（ストレージ含む）・ピン・いいね・行きたい！が削除される |
| **代替フロー** | 3a. 「キャンセル」を押下した場合は削除せずダイアログを閉じる |
| **事後条件** | 投稿がDBおよびストレージから削除され、タイムラインから消える |

---

### UC-08: 写真・地名・地図を確認する

| 項目 | 内容 |
|------|------|
| **概要** | 投稿カード内の写真をスワイプし、対応する地名バッジと地図ピンを確認する |
| **事前条件** | 投稿カードが表示されている |
| **基本フロー** | 1. 投稿カードの写真エリアを左右にスワイプする<br>2. 写真の切り替えに連動して地名バッジが変わる<br>3. 投稿詳細画面では地図上のピンもアクティブな写真に連動して切り替わる |
| **代替フロー** | 2a. 現在の写真にピンが設定されていない場合は地名バッジを非表示にする |
| **事後条件** | 現在表示中の写真に対応した地名・地図ピンが表示される |

---

### UC-09: いいねする／取り消す

| 項目 | 内容 |
|------|------|
| **概要** | 任意の投稿にいいねをする、またはいいねを取り消す |
| **事前条件** | ユーザーがログイン状態である |
| **基本フロー（いいね）** | 1. 投稿カードのいいねボタン（❤️）を押下する<br>2. いいねがDBに保存される<br>3. いいねボタンがアクティブ状態になり、いいね数が+1される |
| **基本フロー（取り消し）** | 1. いいね済みのいいねボタンを押下する<br>2. いいねがDBから削除される<br>3. いいねボタンが非アクティブに戻り、いいね数が-1される |
| **代替フロー** | なし |
| **事後条件** | いいね状態といいね数がDBに反映される |

---

### UC-10: 「行きたい！」を押してスレッドを作る

| 項目 | 内容 |
|------|------|
| **概要** | 投稿の「行きたい！」ボタンを押すとナビちゃんスレッドが自動生成される |
| **事前条件** | ユーザーがログイン状態である |
| **基本フロー** | 1. 投稿カードの「行きたい！」ボタン（✈️）を押下する<br>2. 行きたい！がDBに保存される<br>3. ナビちゃんスレッドが自動生成される<br>4. 導入メッセージ「〇〇の投稿、気になったんだね！どんな旅にしたい？」が送られる<br>5. ナビちゃんチャット画面へ自動遷移する |
| **代替フロー** | 1a. すでに「行きたい！」済みの場合は取り消しのみ行い、スレッドは再生成しない |
| **事後条件** | 行きたい！状態がDBに反映され、ナビちゃんスレッドが作成される |

---

### UC-11: ユーザーをフォローする

| 項目 | 内容 |
|------|------|
| **概要** | 任意のユーザーをフォローする、またはフォローを解除する |
| **事前条件** | ユーザーがログイン状態である |
| **基本フロー（フォロー）** | 1. プロフィール画面でフォローボタンを押下する<br>2. フォロー関係がDBに保存される<br>3. ボタンが「フォロー解除」に変わり、フォロー数・フォロワー数が更新される |
| **基本フロー（解除）** | 1. 「フォロー解除」ボタンを押下する<br>2. フォロー関係がDBから削除される |
| **代替フロー** | 1a. 自分自身はフォローできない（ボタンを非表示にする） |
| **事後条件** | フォロー関係がDBに反映され、フォロー中タイムラインに影響する |

---

### UC-12: ナビちゃんスレッド一覧を確認する

| 項目 | 内容 |
|------|------|
| **概要** | 過去のナビちゃんとの会話スレッド一覧を確認し、続きを相談する |
| **事前条件** | ユーザーがログイン状態である |
| **基本フロー** | 1. BottomTabの「ナビちゃん」タブを選択する<br>2. スレッド一覧が最終更新日時の新しい順に表示される<br>3. 各スレッドにはサムネイル・タイトル・最終更新日時が表示される<br>4. スレッドを選択するとチャット画面へ遷移する |
| **代替フロー** | 2a. スレッドが0件の場合は「まだ相談がありません」を表示する |
| **事後条件** | スレッド一覧が表示される |

---

### UC-13: ナビちゃんに旅行プランを相談する

| 項目 | 内容 |
|------|------|
| **概要** | ナビちゃん（Claude API）と会話して旅行プランを相談する |
| **事前条件** | ナビちゃんスレッドが存在し、チャット画面が表示されている |
| **基本フロー** | 1. メッセージ入力フォームにテキストを入力する<br>2. 「送信」ボタンを押下する<br>3. ユーザーメッセージがDBに保存される<br>4. Claude APIへリクエストを送信する（過去メッセージ＋ユーザー好み情報を含む）<br>5. ナビちゃんの返答がストリーミング表示される<br>6. 返答がDBに保存される<br>7. 会話終了後、ユーザー好みサマリーが更新される |
| **代替フロー** | 4a. Claude APIエラーの場合はエラーメッセージを表示し、再試行を促す |
| **事後条件** | メッセージがDBに保存され、好みサマリーが更新される |

---

### UC-14: プロフィールを確認する

| 項目 | 内容 |
|------|------|
| **概要** | 任意のユーザーのプロフィール情報と投稿一覧を確認する |
| **事前条件** | ユーザーがログイン状態である |
| **基本フロー** | 1. 投稿カードのユーザー名／アバターをクリックする<br>2. アバター・ユーザー名・自己紹介・フォロー数・フォロワー数が表示される<br>3. そのユーザーの投稿一覧が新着順に表示される<br>4. 他ユーザーのプロフィールの場合はフォローボタンが表示される |
| **代替フロー** | 1a. 存在しないユーザーIDにアクセスした場合は404ページを表示する |
| **事後条件** | 対象ユーザーのプロフィールと投稿一覧が表示される |

---

### UC-15: プロフィールを編集する

| 項目 | 内容 |
|------|------|
| **概要** | 自分のプロフィール（アバター・ユーザー名・自己紹介）を編集する |
| **事前条件** | ユーザーがログイン状態であり、自分のプロフィール画面を表示している |
| **基本フロー** | 1. プロフィール画面ヘッダー右上の「編集」ボタンを押下する<br>2. 編集モーダルが開く<br>3. アバター・名前・自己紹介を編集する<br>4. アバターを変更する場合はS3またはローカルにアップロードされ、即時プレビューされる<br>5. 「保存」ボタンを押下する<br>6. モーダルが閉じ、プロフィール画面に更新内容が反映される |
| **代替フロー** | 5a. 「キャンセル」を押下した場合は変更を破棄してモーダルを閉じる |
| **事後条件** | プロフィール情報がDBに更新される |
